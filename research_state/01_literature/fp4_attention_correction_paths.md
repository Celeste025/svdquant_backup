# E016：官方 FP4 attention correction 路径核查

2026-10-02；只读源码，未运行 GPU。**E016 没有遗漏一个已合入的 SM120、同算术合同、无需物化 correction 的开关；但消费融合、compact 布局以及公开的 Q 分块缓解均已存在，不能把它们当新方法。**“未找到”仅限下列主线和相关 PR，不是全领域不存在的断言。

- **FlashInfer 当前主线仍预计算 compact FP32 correction。** 查询主线 commit `1b578de52924c973bd229fe4fd147499ead2781d`（2026-10-02）：K 去全局均值，Q 按 128-token 分组去均值，随后以 FP32 operands 做 `qm @ Kᵀ`，物化 `[B,H,Mpad/128,Npad]`；kernel 将该行加载至共享内存并广播到 Q tile、作为 QK 累加器初值。**应用 correction 已融合进 attention；生成该矩阵尚在 attention 外。** API 与 `delta_correction.cuh` 的 SHA 分别为 `040738c6…9abefc`、`db067b79…0fe`，与 E016 安装文件完全一致。[预处理源码](https://github.com/flashinfer-ai/flashinfer/blob/1b578de52924c973bd229fe4fd147499ead2781d/flashinfer/nvfp4_attention_sm120.py#L130-L172)、[消费源码](https://github.com/flashinfer-ai/flashinfer/blob/1b578de52924c973bd229fe4fd147499ead2781d/include/flashinfer/attention/sm120/nvfp4_attention_sm120/compute/consumer/delta_correction.cuh)。已合入 [PR3838](https://github.com/flashinfer-ai/flashinfer/pull/3838) 修掉的是原先错误的完整 `[B,H,M,N]` 展开；[PR4502](https://github.com/flashinfer-ai/flashinfer/pull/4502) 优化 score-slot 重用/LSE 等，未消除 compact correction。E016 已使用这些修订后的接口，不能复述旧版展开成本。

- **SageAttention3 主线同样物化；开放 PR 已提供分块规避。** 官方主线 `d1a57a54…3b4b5` 的 [api.py](https://github.com/thu-ml/SageAttention/blob/d1a57a546c3d395b1ffcbeecc66d81db76f3b4b5/sageattention3_blackwell/sageattn3/api.py#L75-L92) 用 Triton 同时计算 Q block mean/减均值，但另做 matmul 生成 `delta_s`。官方仓库尚未合入的 [PR394](https://github.com/thu-ml/SageAttention/pull/394)，head `26e839b2…ee4a4`，已实现 128 对齐的 Q chunks、K/V 只居中和量化一次、每 chunk 单独生成/消费 `delta_s`；可自动处理长序列 TMA stride 溢出或显式指定 chunk。它减少一次保留的 correction，**仍逐 chunk 物化，并非 kernel 内即时计算**。[实际实现](https://github.com/thu-ml/SageAttention/blob/26e839b2a87c9990c3c94f79157f76f3295ee4a4/sageattention3_blackwell/sageattn3/api.py#L233-L333) 限定 noncausal、无 mask、block mean。其 exact 测试是作者报告，未在本机复测；Sage 的低精度 matmul 输出再转 FP32，与 FlashInfer FP32 operands 的合同也不同，不能直接宣称跨实现逐 byte 等价。

- **其它公开路径不能当作同合同替代。** TurboDiffusion 主线 `e3d61360…c80b2` 的 [推理改装代码](https://github.com/thu-ml/TurboDiffusion/blob/e3d61360b0eeab60c5cd09ff7d6c1020cccc80b2/turbodiffusion/inference/modify_model.py#L34-L53) 调用 SLA/SageSLA，已读路径中没有独立的上述 correction 融合。FlashInfer 最新 [experimental CAKE](https://github.com/flashinfer-ai/flashinfer/blob/1b578de52924c973bd229fe4fd147499ead2781d/flashinfer/experimental/nvfp4_attention/cake_backend.py#L118-L149) 直接量化 Q/K/V，无此中心化 correction，但只支持 SM103、特定 shape，且换了量化合同，不能称为 E016 的等价 SM120 开关。

**解释边界：** `per_block_mean=False` 已是公开的线性大小 `[B,H,1,Npad]` correction 路径，但改变 Q 中心化与量化误差，不能把 True/False 当作纯内存消融。compact correction 的理论大小不是整模峰值，更不证明延迟瓶颈或长视频 OOM；E016 的完整计时、峰值与误差才回答当前配置的取舍。本核查不建议新增实验或注册贡献。
