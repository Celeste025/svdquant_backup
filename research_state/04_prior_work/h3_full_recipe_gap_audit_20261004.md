# H3 legacy / E065b 与 SVDQuant 配方的剩余差异

2026-10-04；独立源码审计；0 GPU、0 forward，未导入量化包，未改历史源或结果。先读 current_state 与 reports 054/059/060，再核当前源码。本文件不把方法名、当前源码或历史 state 当成历史生产流程证明。

**结论：E065b 是有用的 fixed-smooth、native local-loss carry 对照，但不足以完成“官方 SVDQuant 强基线已经失败”的判断。最实质的未补齐项是 smoothing 候选评价是否含低秩支路、候选族与数值实现，以及 qkv 的 attention-output 校准目标。仅继续固定旧 smooth 的初始化网格不能补齐这些项。**

来源边界：`third_party/deepcompressor` 没有独立 `.git`；`git -C` 实际落在项目 fork（origin Celeste025/svdquant_backup，项目 HEAD `586456bacf74865325ff85c206a4130a82601719`），且含 Wan 和 real_nvfp4 扩展。下表除明确注明外，证据称 **vendored 接口/默认配置**，不假称干净 upstream checkout。Root 已独立固定 upstream commit `69f3473f5e1c1504bae35cc50c7858ef900a9b17`，确认其 SVDQuant 默认 `allow_low_rank=true, g20, rank32, 100/early_stop` 与精确 FP64 SVD；E069 下载/见证由 root 另行保存。本审计不预告 E069 执行结果。

## 最小忠实 H3 接入入口

无需先把整个 H3 强塞进 `DiffusionModelStruct`。可直接接校准器，先完成一个预选 block 的 4 个 linear 接口合同，再推广到200层；该步骤检验实现是否忠实，不设“先改善20%”才能允许建标准基线。

1. 复用 [load_h3_pipeline:106](/home/wjq/workspace/svdquant-exp/scripts/minimax_h3_svdquant_common.py:106) 的 DiT-only 路径；原始64状态在 `results/calib/minimax_h3_svdquant_standard_8p64s/p*/sample_p*_s*.pt`。用 [raw_call_to_block0:304](/home/wjq/workspace/svdquant-exp/scripts/minimax_h3_svdquant_common.py:304)、`run_block:327` 或既有 hook capture 做逐块流式缓存，保留每 case 的真实 kwargs。不要全200层×64状态全量常驻/落盘。
2. 平滑入口：[SmoothLinearCalibrator.calibrate 调用合同:982](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/calib/smooth.py:982)，接 `x_wgts, x_acts, x_mods, eval_inputs, eval_module, eval_kwargs`。便利函数 `smooth_linear_modules` 会在1000–1003原地应用 scale，后续 native exporter 必须只应用一次；不要把已缩放 W 又乘一次 s。
3. LR 入口：[DiffusionWeightQuantizer.calibrate_low_rank:234](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/app/diffusion/quant/quantizer/quantizer.py:234) 最终直接调用 `QuantLowRankCalibrator(...).calibrate(...)`，可不走 model-struct 适配层。保留同一候选的 Q、A、B 与 smooth 绑定；LR hook 要先读未量化的 x_s，不能从 Q(x_s) 读输入。
4. H3 qkv 的 `eval_module` 用现有真实 attention，而非另写 qkv 分解。准确接口在 [minimax_h3_dit_comfy.py:17](/home/wjq/workspace/svdquant-exp/third_party/DiffSynth-Studio/diffsynth/models/minimax_h3_dit_comfy.py:17)：`forward(x, *, rope_freqs, cu_seqlens, max_seqlen)`，内部已含 `[M,3,H,D]` 布局、q/k norm、RoPE、varlen SDPA、out projection。普通 out/fc1/fc2 用其真实 linear。若主动改成 AdaLN-gated block 目标，则另标适配，不能说是默认目标照搬。
5. **必须防止 cache 把 attention 切错，并兼容不同 prompt 的 M。** [SearchBasedCalibrator._parse_ipts:254](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/calib/search.py:254) 对 OutputsError 仍调用 repartition；[TensorCache.repartition:142](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/data/cache.py:142) 先断言全部 tensor 同 shape，再按 shape[0] 切批。直接把 `[M,C]` 交给默认 sample_batch_size64 会切碎 sequence；单加 `[1,M,C]` 或 batch_size=-1 仍不能通过 variable-M 的同形状断言。可行的**待验证接口**是：eval cache 每份只保存 `[1,1]` case_id，batch_size=1；wrapper 从不可变 CPU 字典取该 case 的完整 x 与 rope/cu_seqlens/max_seqlen，调用真实 module，返回原形状 tensor；按原逐 case SSE 求和。不要 pad、拼接 sequence 或复用不同 case 的 kwargs。[search.py:394](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/calib/search.py:394) 的 OutputsError+Layer 路径只 parse eval_inputs，x_acts 原样返回，故另保留 variable-M 的单张量列表用于 [smooth span:302](/home/wjq/workspace/svdquant-exp/third_party/deepcompressor/deepcompressor/calib/smooth.py:302)。必须实际零干预 byte replay 验证该 wrapper 后才能称已接通；本次仅静态确认方案。
6. 先明确两个合同层次：固定 upstream 算法与精确 SVD/默认搜索目标；以及 H3 原生格式、BF16支路、全tensor global/pack 的部署适配。真实 native 校准评价可以作为部署适配，但不应把 QDQ 探针和 native 内核自动视为逐 byte 相同。源语义见证可以纯 AST/小矩阵 CPU 完成，不能据此声称 GPU kernel 已复演。

## 资源与下一决策

已有 E065+E065b 两臂各8候选、8状态、M512 的完整搜索约经历1800秒源阶段与3294.94秒 continuation（包含 capture、导出、诊断和 I/O，不是纯SVD计时）。因此忠实恢复全部配方不应再塞进900/1800秒并把超时当阴性。

确定的工作量上界比未经测量的分钟数可靠：200层×39个 smoothing 候选即7800次 LR 构造；随后100次上限 LR calibration 最多20000次，early-stop可能显著减少。若逐64状态完整评价，平滑约499200次 eval-module 调用，其中qkv约124800次真实attention；LR阶段最坏1280000次模块评价。不是39×100嵌套。精确FP64 SVD相对现有 q40 随机SVD的时间/工作区未知，不能按E065线性外推得出可执行deadline。最大的fc1 `[28672,5376]` 仅FP64权重输入已约1.15GiB，SVD还需分解输出与工作区；宜单矩阵/单块常驻，现有60GiB GPU峰值合同不能直接沿用成已验证结论。

下一项值得做的是 **CPU配方语义见证 + 单块接口接通及成本测量的方案**，目标是决定是否值得承担完整标准基线成本；它不要求局部或完整SSE预先出现正结果。选中与部署绑定、真实 attention 整序列、LR读x_s及无量化回放是进入条件。未获得成本测量前只能预算为多小时级候选工作，不能承诺具体整模型耗时。正式全200层基线应一次冻结平滑/LR/目标/数值规则，避免围绕旧 smooth 连续加诊断。

可停的是“仅增加 fixed-smooth carry 便足以修复完整teacher SSE”的现有特定配方；不能据E061/E065b宣布默认 LR-aware smoothing 或精确官方子空间配方无效。E066 的局部改善不兑现与E068待人评视频也不构成新机制证明。本审计支持补齐公平基线的必要性，不提供新方法或画质优势；用户既有研究授权持续有效，GPU执行前仍须落实具体协议和资源上限，不需重新请求一般研究许可。
