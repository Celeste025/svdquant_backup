# 研究流程审查：先证明丢失了什么能力，再筛机制

2026-10-02；独立 CPU 审查，未运行新推理、未修改冻结证据、未建立新 claim。

**最大的流程错误是把“便于复用的数值诊断”当成研究对象的来源：在尚未确定 BF16 能可靠完成、W4A4 可能破坏的任务前，先要求某个局部机制呈现强信号。** 原生实现与配对正确性工作必要且已经完成；继续围绕旧缓存寻找一个罕见的大交互，并不是目前信息收益最高的选择。

证据不是“实验不够多”，而是实际覆盖错位。[E004](../06_experiments/E004_modality_reweight_results.md) 的干预仅为 block0.fc2 的 B，后49层均BF16；−6.74%未过10%只能停止这个固定对照，不能估计全量化系统中该目标的价值。[E010](../reports/010_20261002_h3_heldout_results.md) 仅两条文字动画/产品广告，沿用旧20步而非本地pipeline默认50步；评价未覆盖明确动作完成率，音频未评。p30的29题全同与p36两题形状下降都没有定义一个可优化的功能差距。[E012](../../results/research/E012_summary.json) 为复用同一轨迹、维持813tokens，在复杂广告里交换光照方向；26个BF16调用证明该局部差分对±1ULP不稳定，**从未验证真实视频是否执行了方向指令，也从未运行native条件对照**。这不是对条件控制损伤的科学反驳。各项STOP的文字边界写得正确，但我们实际的选题空间仍被这些方便的代理结果收窄了。

**最强反对意见：** 小样本功能筛查可能没有新颖性、极易挑样本，且BF16随机生成与量化轨迹分叉可制造假损伤。完全同意；下面只用于决定有没有值得解释的对象，不用于证明新方法，更不复活已被先前工作覆盖的差分损失。若连具体任务能力都不能建立，再精确的机制审计也无从决定论文价值。

**唯一建议的反事实下一步（先预注册，单卡≤90分钟，预算到即停）：** 用两个简短、相反事件顺序的提示和各两个固定seed，共4个case，例如同一固定镜头里“红球先越过左侧标记再越过右侧标记”及反序；明确物体、标记与事件发生标准，不放广告、文字叠加、镜头切换等无关要求。使用本地默认50步作一次明确的新协议，两arm完全相同；50步不被预设为更好。先生成全部4个BF16，逐帧核对事件，只有≥3/4成功才运行全部4个native；保存并报告所有失败，不追加提示/seed补足成功数。评阅时隐藏arm，按预先定义的两次越界时刻判分；保留动作未发生、顺序不可判断、物体身份破坏三个失败类别。复用E009原生与E010生成链路，不开发新评价器或校准方法。8段×50次DiT按已测约7–8秒粗估约50 GPU分钟，TE/VAE与加载预留40分钟；这是预算而非实测。

**什么结果足以改变决策：** BF16不足3/4成功，停止这个任务定义，不能说量化无损；BF16成功且native没有额外失败，停止在该范围追条件控制；至少两个配对case出现BF16成功/native失败、且两个提示均被覆盖，才值得进入独立新seed复验及精度/校准强对照，仍不立论文claim。单个漂亮差异不通过。只允许这一轮封闭筛查，不把“找可见失败”变成无限选题搜索。真正需要纠正的是先后顺序：**先找到有可靠teacher基线的功能缺口，再解释它；不要把未能建立局部代理，当成缺口已被排除。**
