# 第四阶段流程批判：先给复杂性定价，不必先找到能力损伤

2026-10-02；CPU/primary-source 核查，未运行 GPU，未改冻结实验。采用 research-target-reframing 的必要复杂性审查视角。

**我反对把“BF16稳定完成某项行为、量化稳定破坏它”设为整个研究的入口。** 它是论证某种能力损伤的必要对照，却不是降低校准成本、减少部署算子或扩展资源可达范围的前提。E009 已有真实价值：H3 前向 8.260→6.787 s、峰值 allocated 40.86→16.80 GiB；没有可见质量提升不使这组资源收益无效，但仍不能据此声称质量等价。当前程序把“正确性硬约束、代理可解释性、值得继续投入、新颖性”串成全必须通过的门槛，容易先筛掉观察对象，再把没有候选当成没有研究空间。

**E013 暴露的是观测设计与目标冲突。** toward 确实接近，恰因接近至 rho<1.5 被判 unknown；这保护了读出的可解释性，却不能证明 teacher 不具备接近能力。away 先接近、经过再远离，才是该提示未形成干净对照的证据。保持两例 unknown 和此次 STOP 正确；将此升级为“不能继续研究量化”不正确。[E004](../06_experiments/E004_modality_reweight_results.md) 同样如此：普通 B refit 局部改善39–47%、终点改善6.74%未达10%，是限定预算内的停止依据，不是自然效应边界。只量化 block0、后49层BF16，不能替代完整量化下的排序；也不应因此复活普通模态加权作为新方法。

**唯一建议：补齐完整 plain-native NVFP4 与现有 SVDQuant-native 的成本—误差对照。** 我支持 root 的这个建议，因为 E003/E004 的 plain 只改 block0，而 E009 完整原生只测既有 rank32；我们尚未量过整套 smooth+LR 的净收益，就已花很多时间解释它的残余误差。plain 必须从原始 BF16 权重重新量化，取消 smooth/LR，保留相同200目标、group16/scales/舍入约定、bias、非目标层和 BF16 attention；**不能从现有残差 checkpoint 直接删 LR**。这是比较两套部署配方，不能单独归因于 LR。

最小执行范围按 root 拟定 E014 固定为三份已存状态：E009 p1/step0、E010 BF16轨迹 p30/step5 与 p36/step14。各跑完整 BF16/SVD-native/plain-native，同一模型调用，核对已有 BF16 参考；报告双模态 endpoint 误差、50层差异和是否有限。在固定 E009 p1/step0 形状上三臂独立计时（1 warmup+3 repeats），包含全部 packing/smooth/LR，记录启动/前向显存与导出耗时；无校准搜索、无新 prompt/视频/损失。工程验码及独立 decode 是硬约束，数值误差差距不另设任意10%准入门槛。复用 E009/E010 和现有 fast packer，建议总预算20 GPU分钟；p1属旧校准集，p30/p36虽不在旧校准集但均已看过，只作诊断。该步只回答“现有复杂性买到了多少重建改善，付出多少资源”，不把 NMSE 当能力，也不把未融合 SVD 的开销当最优实现下界。plain 明显更差也有价值：证明当前复杂性有必要；若接近或交叉，则今后的方法必须同时胜过这个廉价基线。此次交付止于比较表，不自动扩展方法搜索。

**理论与近邻反证。** group16/E4M3 将跨组幅度差局部化，但组内离群值、权重方向相关性及下游传播仍存在，不能从格式推出 LR 无用。[SVDQuant camera-ready Table 3](https://arxiv.org/html/2411.05007v3) 已显示 FLUX-dev 无GPTQ时，NVFP4 加LR的PSNR为20.3→20.9，INT4为18.5→20.1；有GPTQ时NVFP4无/有LR为21.5/21.4，指标并非单调一致。表格未单列smooth开关，不能把其无LR视为这里的完全plain。[JustQuant Table 9](https://arxiv.org/html/2609.33601v1) 已研究无额外部署分支，但FLUX采用INT4 group64并训练4 H200×18小时；它不等于无训练H3 plain NVFP4已被验证。“不需要SVD”不是新贡献；**必要强基线也不需要先通过新颖性审查才值得做。**
