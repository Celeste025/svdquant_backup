# E092 — H3 FC2 INT4 group-128 smoothing statistic

- Experiment mode: exploration.
- Problem addressed: Is the small/unstable SmoothQuant gain seen under K16 NVFP4 mainly a consequence of NVFP4's fine block granularity?
- Hypothesis: For signed INT4 W4A4 quantized in contiguous K-groups of 128, p99-derived static channel smoothing yields a larger held-out output-NMSE reduction than the same recipe under NVFP4, or at least changes the relative ranking of p99 versus absmax.
- Decision informed: Whether to pursue robust static channel smoothing for H3 INT4 rather than NVFP4, or pivot to dynamic/targeted outlier handling.
- Minimum valid setup: Same full H3 block-25 FC2 BF16 weight and complete p11 step-0 calibration / p1 step-0 held-out input as E090/E091; plain, absmax, and p99 channel smoothing on a common alpha grid; signed round-to-nearest W4A4 with independent per-row contiguous-K128 activation scales computed online and per-output-row contiguous-K128 offline weight scales; original BF16 output reference. Add the identical signed-INT4 quantizer at K-group 16 as a numerical granularity control. Select alpha on p11 only and report p1. This is an error-only two-call diagnostic, not a deployable INT4 kernel or generalization claim.
- Invalid cheap proxy to avoid: INT4 weights with BF16 activations; using p1 to select alpha; changing group size or clipping only in one arm; interpreting dequantized BF16 GEMM timing as native INT4 speed.
- Expected outcomes / decisions: If p99 selected on p11 beats plain INT4 on p1 by a material margin, expand to more prompts/layers and block outputs. If gain is small or reverses, stop the one-call static-p99 recipe and target rare outliers/dynamic scaling instead. If both absmax and p99 help, evaluate whether INT4 granularity truly differs from NVFP4 under a matched activation policy before attributing causality.
- Stop condition: One complete full-shape numeric report and verification of finite outputs, non-overlapping calls, quantization ranges/group shapes, and a small-row integer-code reference gate; no extra performance tests in this experiment.
- Evidence: Necessary = full-shape p1 held-out W4A4 output NMSE against plain under identical quantizer. Supporting = p11 fit NMSE, alpha and operand error diagnostics. Cuttable = tokenwise surfaces, video generation, broad alpha search. Future work = native INT4 kernel timing and broader prompt/step/layer validation.
