# E108 — H3 closed-loop oracle previous-error correction, k=0.6

- Experiment ID: E108.
- Mode: exploration / closed-loop validation of E107's teacher-forced diagnostic.
- Problem addressed: E107 found that `e_t - k e_(t-1)` markedly reduces paired output NMSE on saved BF16 trajectories. Does the same rule alter actual generated videos when correction is applied at every step on the arm's own evolving input?
- Hypothesis: Applying `Q_t - 0.6 e_(t-1)` from step 1 onward, where `e_(t-1)` is the prior step's true paired `Q-BF16` output error on this arm's own trajectory, reduces complete-DiT output error and BF16-relative final video divergence compared with the original SVDQuant rollout. Step 0 remains unmodified Q.
- Decision informed: Whether temporally coherent error is worth targeting with a deployable error predictor or trajectory-aware calibration objective.
- Minimum valid setup: Fixed race prompt 16/seed 20026 and clap prompt 161/seed 38001610; E101/E105 rank-32 dynamic-scale checkpoint, 576×1024, 124 frames, 20 steps, CFG 1, video/audio flow shifts 12/3, CPU-seeded noise, original tiled VAEs. At every step, run BF16 and SVDQuant DiT on identical *current E108-arm inputs*. For each modality separately, use the preceding raw paired error before any correction; never substitute the previous corrected residual. Return BF16-typed corrected outputs so scheduler and downstream inputs retain the original runtime dtype. Record raw target and corrected video/audio MSE/NMSE, prior-error cosine, previous/current error RMS ratio, and BF16 rounding distortion. Verify step 0 reproduces E101 SVDQuant output and correction is exactly zero. Save all 20 steps and terminal latents, then separately decode to validated 124-frame MP4s. Use GPU4/5 in parallel if ≥45 GiB free; do not disturb E106 on GPU6/7.
- Invalid cheap proxy to avoid: Correcting only the saved E103/E104 BF16-trajectory outputs and calling it a generated result; using previous errors from another arm or prompt; using corrected residual rather than raw `Q-BF16` as the next correction state; silently changing output dtype, scheduler, seed, or checkpoint; treating decoded RGB distance as perceptual quality or claiming deployment feasibility.
- Expected outcomes and decisions: If both cases have smaller corrected output NMSE and visibly BF16-closer videos, investigate how to estimate the recurring error from quantized state without a BF16 forward. If local NMSE falls but videos do not improve, temporal teacher-forced predictability is insufficient for closed-loop quality. If per-step correction worsens, inspect feedback drift and k sensitivity before designing a method.
- Stop condition: Both cases complete all 20 paired steps, finite video/audio metrics, hash-checked state/media, and paired visual/pixel comparison, or a documented numerical/resource failure prevents a valid result.
- Evidence classification: Necessary closed-loop check after E107, but still a two-case oracle, not a deployable quantization method or general video-quality result.
