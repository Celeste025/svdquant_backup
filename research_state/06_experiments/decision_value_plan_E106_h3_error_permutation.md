# E106 — H3 complete-DiT error-value permutation

- Experiment ID: E106.
- Mode: exploration / mechanism discrimination after E105.
- Problem addressed: E105's equal-energy flat and Gaussian errors gave much smaller BF16 rollout divergence than genuine SVDQuant error, but changed both error positions and the marginal error-value distribution. Is the association between original error values and tensor coordinates important when the values themselves are retained?
- Hypothesis: Permuting genuine signed error values independently within each complete-DiT video and audio output at every denoising step will yield a closed-loop video closer to BF16 than original SVDQuant at essentially unchanged per-step NMSE. This would implicate error placement/structure, but not identify which coordinate axis matters.
- Decision informed: Whether to prioritize positional/signed error structure over marginal heavy-tail suppression or plain NMSE reduction in the next quantization calibration objective.
- Minimum valid setup: Reuse E105 race prompt 16/seed 20026 and clap prompt 161/seed 38001610; same rank-32 dynamic-scale state, 576×1024, 124 frames, 20 steps, CFG 1, video/audio shifts 12/3, CPU noise, tiled original VAEs. On the *current permutation-arm input* at each step, run full BF16 and SVDQuant DiT with identical arguments, compute signed FP32 `e = Q-BF16`, draw a deterministic uniform permutation of all elements independently within each modality, then return `BF16 + permute(e)` rounded to the original BF16 output dtype. This preserves the FP32 error multiset exactly before mandatory BF16 casting. Record target/realized MSE and NMSE, BF16 rounding distortion relative to target error energy, and original-versus-permuted same-location cosine. Require every video/audio step's realized MSE within 0.5% of the paired quantized MSE; require rounding distortion below 0.5% of target error energy. Save 20-step reports, terminal latents, and separately decoded videos. Use two GPUs in parallel after VRAM/preflight checks. Compare against existing E101 BF16/SVDQuant and E105 flat/Gaussian/tail controls with the same descriptive decoded RGB divergence metric.
- Invalid cheap proxy to avoid: Permuting the 20 saved E103/E104 BF16-trajectory errors after this arm's latents diverge; accidentally permuting BF16 output values rather than signed errors; treating BF16-rounded output as a bitwise-exact permutation; using a different seed/scheduler/checkpoint; or declaring a perceptual-quality win from H.264 pixel NMSE alone.
- Expected outcomes and decisions: If permutation behaves like the equal-energy independent-noise arms, positional organization of the real error values is a stronger suspect than its heavy-tailed marginal; next test axis-preserving shuffles/sign randomization. If it remains close to original SVDQuant, the retained error-value distribution or nonlinear/latent-dependent properties may matter; next compare shuffled signs and tail-clipped marginals. If between them, quantify effect and still isolate axes before designing a method. If match or fidelity gates fail, report failure, not a positive mechanism claim.
- Stop condition: Both 20-step permutation videos and per-step validation complete, or a documented resource/numerical failure prevents a valid conclusion. Two chosen prompts and one permutation seed per prompt are exploratory only.
- Evidence classification: This is necessary mechanism-discriminating evidence for the E105 interpretation, not a standalone paper-level generalization claim. Spatial/channel/temporal axis isolation and larger prompt/seed sampling are follow-up work.

Pre-execution saved-BF16-trajectory numerical gate: across both E103/E104 20-step captures, full-element permutation followed by BF16 cast changed MSE by at most 0.072% and incurred at most 0.038% rounding distortion relative to original error energy. This gate is preliminary; the closed-loop E106 trajectory must be checked independently at every step.
