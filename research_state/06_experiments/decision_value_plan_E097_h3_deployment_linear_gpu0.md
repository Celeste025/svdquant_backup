# E097 — Isolated H3 native quantized-linear deployment benchmark on GPU 0

- **Mode:** exploration / deployment-baseline completion.
- **Problem addressed:** Earlier full-shape H3 low-bit linear timings on GPU 4–6 were invalidated by concurrent workloads. Which genuinely deployable native kernels are fast and accurate on idle RTX PRO 5000 Blackwell?
- **Hypothesis:** Paired, idle-GPU measurements of real vLLM/FlashInfer low-bit operators will yield stable latency and stage splits, unlike shared-GPU provisional medians, and reveal which formats are competitive with BF16 at H3's actual FC2 shape.
- **Decision informed:** Which hardware/operator paths are legitimate performance baselines for subsequent H3 quantization work.
- **Minimum valid setup:** One registered real `blocks.25.mlp.fc2` call, p1 step 0 input `[22400,14336]`, original BF16 weight `[5376,14336]`, same BF16 output target. GPU 0 pre/post idle check and CV gate ≤3%; at least 50 warmups, 11 CUDA-event batches, 30 repetitions per batch where supported. BF16 GEMM; vLLM W8A8 dynamic per-token INT8 + native integer GEMM; vLLM group-128 INT4 W4A16 Marlin; FlashInfer native NVFP4 W4A4 online block-16 activation pack + GEMM with independently calibrated second-level scale; native NVFP4 W4A16 weight-only GEMM. Exclude offline weight quantization/repacking and cold JIT from steady-state online timing, but report them separately if measured. Retain output NMSE and non-overlapping component times. Try supported native backend alternatives for NVFP4 when feasible, accept only numerically valid stable runs.
- **Invalid cheap proxy to avoid:** BF16 QDQ simulated GEMM, TorchAO's known slow W4A16 operator presented as Marlin, missing online A quantization for W8A8/W4A4, per-call amax cost falsely made mandatory for calibrated-scale deployment, or silently naming unsupported INT4 W4A4 a GPU baseline.
- **Expected outcomes:** Stable native runs support same-shape latency/accuracy tradeoffs. Unstable or unsupported kernels remain explicitly provisional/unsupported. A native path slower than BF16 is real but not called efficient at this shape.
- **Decision for each outcome:** Adopt only stable, numerically gated, native paths as deployment-operator microbenchmarks; never extrapolate a one-linear result to full DiT latency or generated-video quality.
- **Stop condition:** One full-shape call per accepted path, at most two NVFP4 backend variants; do not tune shape or quantization parameters to manufacture a speedup.
- **Evidence class:** Necessary to replace E088 contention-affected timing; full-engine deployment remains future work.
