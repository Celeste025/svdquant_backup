# E105 — H3 full-DiT output-error interventions

- Experiment ID: E105.
- Mode: exploration.
- Problem addressed: Does the observed non-Gaussian, structured rank-32 SVDQuant complete-DiT output error matter for closed-loop MiniMax-H3 generation beyond aggregate per-step NMSE?
- Hypothesis: Removing the largest signed errors or replacing structured quantization errors by independent equal-energy noise may alter final videos, even when the latter two arms match the quantized local NMSE.
- Decision informed: Whether to prioritize rare output-error tails and/or error pattern control in future quantization research.
- Minimum valid setup: Race prompt 16/seed 20026 and clap prompt 161/seed 38001610, 576×1024, 124 frames, 20 steps, CFG 1, video/audio flow shifts 12/3, CPU-seeded original noise, tiled original VAEs. Use the same rank-32 dynamic-scale SVDQuant checkpoint as E101/E103/E104. For each arm and each *current closed-loop input*, run BF16 and SVDQuant full DiT on exactly the same call. Do not replay E103/E104 BF16-trajectory errors after the arms diverge. Preserve the original scheduler, text embedding, patch/unpatch, output dtype, and video/audio ordering. Apply the following rule separately to video and audio output elements:
  - `tail_restore`: let `e=Q-BF16`, compute its mean and population standard deviation over the current modality output, replace Q elements with BF16 where `|e-mean(e)| > 4 std(e)`; report removed element and squared-error shares. If a particular modality/step has no such elements, leave it unchanged. This arm intentionally lowers NMSE and is not equal-energy.
  - `rademacher_flat`: inject `BF16 + sign_i * sqrt(mean(e^2))`, independent equiprobable signs, then BF16-round and adjust the common amplitude until realized NMSE is within 0.5% relative of the current Q-vs-BF16 NMSE. If BF16 rounding jumps discontinuously over the target, use deterministic random assignment between the two sub-ULP-separated bracketing amplitudes and record both amplitudes/fraction; this is a rounding accommodation, not a spatial error-pattern source. An all-zero or nonfinite target is a failure, not silently approximated.
  - `gaussian`: inject independent N(0,1) errors, normalize sampled error energy to `mean(e^2)`, then BF16-round and adjust amplitude to the same 0.5% relative NMSE tolerance. Use intervention-specific deterministic RNG seeds, never rely on global model RNG state.
  The target is recomputed on each arm's own trajectory; thus across-arm per-step target NMSE may differ once the latents diverge. Reuse existing matched BF16 and original SVDQuant videos as visual controls. Verify first-step BF16/SVDQuant outputs against E101 paired metrics. Save per-step target/realized NMSE and intervention diagnostics. Decode from saved terminal latents in a separate VAE-only process to limit peak memory.
- Invalid cheap proxy to avoid: injecting cached BF16-trajectory errors into a divergent rollout; comparing error fields with unmatched NMSE; changing scheduler or output dtype; treating H.264 pixel distance as perceptual quality; claiming a population effect from two selected prompts.
- Expected outcomes and decisions: If tail restoration gives a visibly disproportionate improvement despite its modest NMSE reduction, investigate targeted tail suppression; otherwise deprioritize hard outlier correction. If flat/Gaussian matched-NMSE arms consistently look better than original SVDQuant, study the residual error's spatial, temporal, channel, or cross-modal structure with more isolating interventions; if similar or worse, magnitude/timestep effects or independent noise propagation may dominate. Disagreement between the two prompts remains a prompt-specific result.
- Stop condition: All six requested videos and per-step validation are complete, or a documented resource/runtime failure prevents a valid arm; never label a partial rollout complete. No formal perceptual-quality or causal-pattern claim without blind review or controlled follow-up.
- Evidence: Necessary for deciding which mechanism to study next; not sufficient as a paper-level quality claim.

## Execution safeguards

Use named tmux sessions, one case per GPU where capacity permits, and stage large latent/media data on `/data1`. Before heavy work, run one-step BF16/quantized equivalence, intervention-energy, finite-output, and VRAM preflight. Do not terminate co-tenant GPU jobs. Record state hash, source manifests, current GPU free memory, timings, and failures. Pair all videos by the same prompt and seed; compare generated visual content qualitatively, while labeling pixel metrics as rollout divergence only.
