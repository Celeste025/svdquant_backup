# 031：投影量化改变了选块，但没有形成明显的预算膨胀

2026-10-03。E035 捕获、CPU 路由及独立复核均完成。**三个预定层的物理块预算净增仅 0.37%–0.90%，有效 token 对净增同样不到 1%；停止这次“量化造成稀疏预算膨胀”的系统假设，不启动稀疏消费者实验。** 这是当前样例上的投入决策，不是证明所有稀疏后端没有时延或质量影响。当前仍无可投稿核心贡献，研究目标继续。

## 做了什么

固定原 E014 的 `e010_p036_s14` BF16 teacher 状态及 blocks 0/24/48。执行一次完整 BF16 DiT，保存三个 attention 的真实输入、原 norm/RoPE 参数及 BF16 Q/K/V；再将各层 qkv projection 替换为已验证的 SVD-native NVFP4 导出，在**同一完整输入**上重放原 attention 前处理，捕获后立即截断。实际 1 DiT、102 BF16 SDPA、3 原生 scaled_mm；39.72 秒完成，未运行额外 attention。历史 teacher 输出漂移为零，仅作报告而非科学门槛。

投影保留全部 22,592 tokens，随后按原有效长度取 22,539。CPU 路由复用官方 H3 VSA 三维分组和 FP32 有效 token 均值：11 个文本/音频前缀块、200 个视频块，tile=(4,4,8)，含所有真实时空尾块。视频块按 FP32 pooled QK 的累计概率达到 p=.9 选块、至少 4 块，再保留全部前缀键；前缀 query 稠密。它是**显式累计概率诊断适配**，不是原固定 top-k VSA 产品。正式路由前已按原 BSA 代码澄清 CDF ≥ p 的边界；冻结 capture/plan 未改，旧未执行检查保留。

## 结果

每层共有 11,200 个 video query/head 行。这些行来自同一个模型状态，不是独立视频样本。

| 层 | BF16 / native 物理块数 | 物理块净增 | 有效 token 对净增 | 换过选块的行 | 同物理预算但换块的行 |
|---|---:|---:|---:|---:|---:|
| 0 | 1,244,039 / 1,248,654 | +0.371% | +0.370% | 8,676（77.46%） | 2,481 |
| 24 | 831,698 / 839,220 | +0.904% | +0.884% | 9,017（80.51%） | 1,773 |
| 48 | 695,594 / 699,013 | +0.492% | +0.468% | 7,129（63.65%） | 1,586 |

“很多行改变”主要意味着每行少量边变化，不能等同于大幅工作量变化。每 video query 平均净增分别为 0.412、0.672、0.305 块，行增量中位数均为 0；video-mask Jaccard 为 .97577、.94739、.95861。

按 head 汇总，预算增/减/不变分别为 36/19/1、46/10/0、39/12/5，故并非所有 head 膨胀。逐行正增量合计为 7,423/10,739/6,118 块，负增量为 2,808/3,217/2,699 块；完整逐行及逐 head 数组已保存，没有只保留净值。前缀恒定成本每层 253,176 物理边；有效 token 统计使用真实块长度，不把 padding 算作有效工作。

路由 CPU 执行 18.14 秒；独立汇总 1.42 秒，均未初始化 CUDA。独立脚本从六份小 score/mask artifacts 重建整数分组、按原 BSA 选择规则复算 mask/counts 及上述统计。Q/K 数值误差由原路由读取真实配对数据计算；独立小文件汇总没有重复读取大 QKV，明确不冒称独立复算该项。

## 判断与下一步

现有证据不足以支持继续搭建“量化预算膨胀”方法。没有运行稀疏 consumer、同预算 mask 干预或完整视频，因此不声称时延无变化、teacher mask 更优或视频质量不受影响；也不通过扩大阈值/样例网格寻找更漂亮的故事。量化与稀疏联合、teacher 蒸馏和动态预算校准已有直接先例，见[有限近邻核查](../04_prior_work/sparse_workgraph_quantization.md)。

下一步转向 N1 的一个具体依赖核查：在投影后打包 FP4 再作跨卡 All-to-All 时，Q 块均值校正是否还需要远端 BF16 K；现成实现在哪侧生成和消费校正？结合 E034 已有连续粗中心消费者，只比较数据依赖和字节账本，先把 global-Q 校正、K4 重建、BF16 通信列为强基线。若既有 ownership 即可消除依赖，则直接结束；当前不写新 kernel、不启动多卡实验，不把低秩或充分统计量的代数改写当贡献。

本轮 GPU/CPU worker 均已退出。最近资源快照 GPU 0–5 空闲，6–7 被其他任务占用；后续启动前重查。
