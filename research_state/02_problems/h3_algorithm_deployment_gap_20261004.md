# H3 算法 × 部署约束：有界筛查，当前不立项

2026-10-04。**本轮新增可立项问题：0。** 仅读 current_state、报告049/061及既有部署/近邻笔记；一次定向检索后读主源，无 GPU、无代码、未使用 E067 结果选题。旧 F1/F2、深度反馈、通用跨步、QAD、稀疏预算和 attention 的有限阴性不外推成普遍不可能，也不换名重开。

唯一筛查的问题是：**能否用一份紧凑、可渐进展开的权重表示，同时提供原生 NVFP4 W4A4 档和较高精度档，避免保存两套完整权重，并使每一档的真实内存/时延收益成立？** 输入是同一高精度权重及明确的两个部署预算，输出须包含可直接被各档算子消费的码、尺度和必要增强信息；增强信息、转换缓冲及额外 GEMM 都计入成本。动机来自表示与消费格式的约束，不能借 E066 的局部/整模排序反转作证，也不是逐层加权或更强校准。

最近邻已覆盖大部分叙事：[MatGPTQ](https://arxiv.org/html/2602.03537v1) 直接研究单整数 checkpoint 的多精度切片、跨位联合 PTQ 和预算内逐层配置；其 §3.2 明示浮点指数使直接 MSB 嵌套困难，§4 的计算路线先将权重解到 16 位。因而它没有直接提供上述 native NVFP4 消费合同，但“一个模型支持多个预算”本身已不是剩余。另，[NVIDIA 的 Nemotron 3 Ultra 部署说明](https://developer.nvidia.com/blog/creating-the-nvidia-nemotron-3-ultra-nvfp4-checkpoint-with-nvidia-model-optimizer/) 已展示同一 NVFP4 checkpoint 在 Hopper 使用 W4A16、Blackwell 使用 W4A4；跨硬件可加载也不是新问题。

**目前无法说明简单组合为什么不够。** 直接保存 NVFP4 加增强残差，属于普通分层编码/残差分支；更高精度母码在加载时生成 NVFP4，则可能已解决需求。若只剩 E2M1/E4M3 格式转换或新 kernel，按用户约束属于工程。尚未提出一个由原生乘法约束必然产生、且这两种强替代不能解决的表示冲突，不能因近邻未测 H3 而认领新颖。

具体缺证是：H3 尚无经独立质量评价的多个精度—成本档，也无要求运行中切档且加载转换/双驻留确实超预算的实际工作负载。报告049的 native 加速和报告061的同输入 SSE 不提供这两项证据。当前保存数据至多支持存储字节账，不能诊断上述需求。**停止本候选，不启动实验。** 只有后续出现明确部署合同，且普通加载时转换或固定混合精度无法满足时，才值得先做成本可行性判别；这不是要求立项前已有阳性，而是避免把人为增加的格式约束当成科研问题。
