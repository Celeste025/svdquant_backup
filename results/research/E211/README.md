# E211：原版 DraftMap 开销占比

相同真实 480p/124 帧 QKV。90/10 使用本轮 E211，10/10/skip80 使用 E210。分母为原版 full API 的每次调用时间。评分与排序直接取 CUDA kernel profile；池化集成在 operand preparation 中，使用原版 prepare 与同粒度缓存复用 prepare 的差值作近似。此增量不是独立 kernel 的严格隔离测量。

| 预算 | 粒度 | 评分+排序 ms / 占比 | 含池化增量估计 ms / 占比 |
|---|---|---:|---:|
| 90% NVFP4 + 10% INT8 | Q128K128 | 0.35 / 1.2% | 1.64 / 5.5% |
| 90% NVFP4 + 10% INT8 | Q64K64 | 0.53 / 2.0% | 1.05 / 3.9% |
| 10% NVFP4 + 10% INT8, skip80% | Q128K128 | 0.37 / 2.6% | 1.65 / 11.4% |
| 10% NVFP4 + 10% INT8, skip80% | Q64K64 | 0.53 / 4.1% | 1.05 / 7.9% |

不包含约 0.02–0.03ms 的物理路由物化；不把原版和概率缓存版总耗时差直接等同于 map 开销，因为两者选块和主 kernel 工作分布不同。PyTorch profile 的父子事件不重复相加，跨流固定开销也不简单相加。未生成视频或修改算子。
