## 方法与验证

- Q128 × K128 tile；FP32 计算 BF16 输入的缩放 QK，并对包含有效前缀的所有 key 做 softmax。只为视频到视频的块打分；边缘块排除 padding。
- 每个 head 内全局排序，最高的约 10% 块使用 INT8，随后约 15% 或 90% 使用 NVFP4。保留预算按现有 Hamilton 分配规则取整；无 anchors。前缀使用 INT8 路径，所有方案一致。
- 原版 DraftMap 使用 maxpool_weight=0.2；随机选块固定种子 196。NVFP4 使用仓库现有逐层校准值。随机对照只测试一个种子。
- 小尺寸输入对照直接计算验证全部四种分数、前缀 softmax 和边缘块；另用超过 20 个元素的 tile 验证 Top-20。每次外部路由都解码并核对排序、各精度块数，然后调用实际 SM120 INT8/NVFP4 算子。四个输入均核对 E187 SHA-256。
- 单次算子输出不是视频质量，结果不代表 PSNR / LPIPS 或推理加速；真实注意力 oracle 的开销未作为加速数据统计。四个捕获并非独立 prompt，结果不能支持普遍性或显著性结论。
- 四份 JSON 包含每个 head 的视频及前缀 NMSE、实际块占比与环境记录；CSV 是便于分析的逐捕获汇总。
