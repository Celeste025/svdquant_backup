# E206：合并概率统计与 attention 分母累加

有限优化：在 capture_probability_from_exp 内复用行内求和，同时更新 d，省去原来的第二次 accumulate_d。Q128×K128 路由和缓冲区格式不变。保留候选为当前实现。

同 E205 的真实赛车 480p、124 帧、step0 layer25，全 56 heads；本轮只做简单数值检查、计时和一次 profile，不跑视频。

| 指标 | E205 | E206 |
|---|---:|---:|
| 首步 full API ms/层 | 36.06 | 35.50 |
| 后续复用 ms/层 | 28.50 | 28.50 左右 |
| spill requests | 167,715,968 | 243,136,768 |

收益小，进行了 A/B/A 对照：原版 31.1429 / 31.1383ms，候选 30.5745ms，原版两次均值为 31.1406ms，candidate kernel 下降约 1.82%。这组 A/B/A 仅测 native capture，不含末尾概率 map 归约；不与 full API 数字混用。

数值：full API 首步相对原 dense INT8 输出 NMSE 6.80e-11；map 与两遍概率版的全部路由指纹一致，后续复用输出 NMSE 为 0。

本轮并未消除 spill，其请求数反而增加，但运行时间有小幅稳定改善，因此未将 spill 数量作为唯一取舍依据。尚未降低统计缓冲区显存占用，也未验证其他分辨率和长序列。

A/B/A 结束时已恢复候选源码。运行时使用独立 JIT 扩展，下次调用会检查并更新依赖；source/ 保留本轮相关源码快照，旧报告均未修改。
